# Моя сеть — GitHub Pages

Бесплатный сайт и независимый сборщик публичных VLESS-конфигураций. Cloudflare, VPS, домен и платные API не требуются. GitHub Pages раздаёт только сайт и подписки, VPN-трафик идёт к сторонним публичным серверам.

## Размещение

1. Загрузите содержимое проекта (включая .github/workflows/update.yml) в публичный репозиторий с основной веткой main.
2. В Actions запустите Update GitHub Pages subscriptions. При загрузке через веб-интерфейс workflow запускается автоматически после коммита в main.
3. В Settings → Pages выберите Source → GitHub Actions. Публикация выполняется официальными upload-pages-artifact / deploy-pages. Ветка gh-pages используется для сохранения последней подписки.
4. Адрес сайта: https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/ . Ссылка подписки Happ: тот же адрес + happ.json. Обычный список VLESS: sub.txt.

Ссылка подписки появится только после успешной проверки хотя бы одного узла. Проверка запускается каждый час и вручную. При неудачном обновлении сохраняется прошлый список и показывается предупреждение. При первом запуске без рабочих узлов сайт сообщает об этом и не выдаёт пустую подписку.

## Как проверяются узлы

config.json содержит прямые независимые источники и manifest автора, из которого выбираются готовые FAST-подписки. Поддерживается VLESS TCP/WS/XHTTP/gRPC с TLS/Reality. Дубликаты удаляются. Из до 10 000 разобранных конфигураций случайно выбираются до 400 кандидатов на запуск, чтобы каждый раз не проверять один и тот же первый блок. Параллелизм — 4, в каждом из двух профилей до 15 узлов по времени HTTPS-запроса.

Каждый кандидат запускается в отдельном процессе Xray с локальным HTTP-прокси. Успехом считается HTTPS-ответ 204 от тестового адреса через этот прокси. Доступный TCP-порт сам по себе не считается рабочим VPN. Приватные адреса не проверяются. Проверка адресов учитывает публичные IPv4 и IPv6, включая DNS-ответы с обоими семействами.

Выпуск Xray 26.10.21 закреплён; архив сверяется по SHA-256 из официального GitHub release. Xray и curl нужны только сборщику, посетитель сайта ничего не устанавливает, кроме своего VPN-клиента.

## Локальные команды

Требуется Node.js 22+.

- npm test — тесты разбора и преобразования конфигов.
- node collect.mjs --dry-run — загрузка и разбор источников без сетевой проверки узлов.
- node collect.mjs — полная проверка; Xray и curl в PATH, либо XRAY_BIN и XRAY_LOCATION_ASSET заданы в окружении.
- node build-site.mjs — подготовить dist/ со страницей и отчётом. CHECK_SUCCEEDED=true задаётся только после успешного сборщика.

Содержимое dist/ создаётся автоматически и исключено из Git основной ветки. Ветка gh-pages содержит публичные подписки и сайт. Не добавляйте в источники приватные/платные подписки: результаты публикуются открыто. Переданные пользователем личные конфиги в проект не включены.

## Ограничения

Это бесплатный агрегатор публичных серверов, а не собственная серверная сеть и не копия неизвестного каскада автора. Владельцы серверов могут их выключить. Проверка из GitHub не подтверждает доступность из сети конкретного оператора или работу при белых списках. Режим WHITE исходных источников не является гарантией обхода ограничений.

GitHub Pages не позволяет установить произвольные HTTP-заголовки подписки; поэтому JSON Happ доступен по обычному URL, без фиктивных 300 ГБ и срока действия. Импорт в конкретную версию Happ нужно проверить после публикации.

## Проверено локально

Разбор источников, генерация страницы, запуск Xray и валидность сгенерированного конфига проверены. В первоначальном наборе из 24 кандидатов не было подтверждённых подключений из текущей сети. Публикация и реальный запуск GitHub Actions проверяются отдельно после размещения. Исследование репозиториев автора — RESEARCH.md.

## Использованные наработки автора

В config.json подключены проверенные внешние источники из списка kort0881/vpn-checker-backend, с исключением его собственных репозиториев. Снимок 66 внешних адресов и лицензия MPL-2.0 сохранены в upstream-sources.json, THIRD-PARTY.md и LICENSE-MPL-2.0.txt. После исправления обработки IPv6 первый успешный сбор GitHub подтвердил 5 узлов; итог следующего запуска может отличаться.

## Два профиля с автовыбором

В happ.json ровно два профиля: «Обычные» и «Белые списки». Внутри — Xray observatory + leastPing с проверкой каждые 30 секунд. Ключи предварительно проверяются HTTPS-запросом. Источники включают независимые списки и актуальные FAST-подписки автора из subscriptions_list.txt. Файл источников автора загружается заново каждый час, ссылки не фиксируются вручную. Группа белых списков определяется источником, а не наличием слова WHITE и не геолокацией как гарантией. Проверка GitHub не подтверждает обход ограничений оператора.

При нуле новых узлов в одной группе сохраняется её прошлый пул с отметкой об устаревании. При отсутствии прошлого пула профиль этой группы блокирует подключения. Если весь сбор не дал результатов, остаётся прошлый опубликованный файл. При первом успешном обновлении после перехода нужно обновить существующую подписку в Happ.

На странице есть запасная ссылка подписки через Яндекс Переводчик: она доставляет только JSON. Исследование транспортов: TRANSPORTS.md. Туннели через Яндекс Документы/Телемост не подключены, так как требуют второй стороны, которой у пользователя нет.

Проверка текущего изменения: 12 автоматических тестов, Xray Configuration OK для объединённого профиля, управляемый тест переключения с HTTP 204 до и после отключения основного выхода. Проверка переключения выполнена на локальном стенде, а не в Happ и не при ограничениях мобильного оператора.

## Российские сервисы напрямую

В обоих профилях перед правилом автовыбора стоят прямые маршруты geosite:category-ru, geosite:yandex, geosite:vk, домены .ru/.рф/.su и geoip:ru. Используется AsIs: домены не разрешаются принудительно перед отправкой в VPN. Российские домены определяются по спискам и суффиксам, российские IP — для соединений, переданных приложением как IP. Локальные приватные сети по прежней политике блокируются. Все остальные назначения идут в VPN-пул; при отсутствии узлов не происходит общего перехода на прямой интернет. После изменения нужно обновить подписку в Happ. Проверено 13 тестами и Xray Configuration OK с реальными geosite/geoip файлами.

Лимиты: до 400 проверяемых кандидатов за запуск (до 200 на группу), до 15 подтверждённых узлов внутри каждого профиля. Если проверку прошло меньше, публикуется фактическое число без заполнения нерабочими узлами. Метка «Белые списки» основана на источниках, а не на проверке из сети оператора пользователя.

Уточнение классификации: готовые категории автора RUSSIA (FAST) и EUROPE (FAST) добавляются в обычную группу. География сервера и суффикс WHITE (живой при проверке автора) не доказывают обход белого списка. Whitelist-группа получает кандидатов из явно заявленных whitelist-источников (wl, WHITE-SNI/WHITE-CIDR). Это метаданные источника; проверка на стороне GitHub остаётся общей HTTPS-проверкой.

## Импорт с телефона

На сайте есть QR-код постоянной ссылки happ.json. Сканировать его нужно в Happ. Изображение генерируется локально при сборке, сторонние QR-сервисы не используются. Обновление узлов не меняет QR. Скачать изображение можно прямо со страницы.

Исправление формата Happ: оба JSON-профиля содержат локальный SOCKS 127.0.0.1:10808, HTTP 127.0.0.1:10809 и DNS. В качестве стартового/резервного выхода используется проверенный VPN-узел pool-0, а не blackhole. При отсутствии любых узлов интернет за пределами прямых правил остаётся заблокированным.


LarpVPN используется только как диагностический образец формата. В конфигурации источников LarpVPN отсутствует; его серверы в подписку не добавляются.

Последние исправления: SOCKS/HTTP-входы для Happ, явный DNS, AsIs вместо принудительного DNS-разрешения, резервный VPN-выход pool-0. Источники LarpVPN отключены; ранее помеченные JSON-узлы исключаются из сохранённых пулов. Генерация и проверка формата выполняются перед каждой публикацией. Сайт отдельно показывает время проверки узлов и сборки профилей в МСК. Отсутствие синтаксической ошибки не гарантирует доступности публичных серверов из ЛДС.

Дополнительно подключены собственные файлы locally-checked-*.txt: публичные ключи из исходных независимых списков, прошедшие проверку из текущей сети (1 обычный, 2 whitelist-кандидата с ответом YouTube). Совпадений с ключами контрольного LarpVPN не обнаружено. При сборке они проверяются заново и имеют приоритет до шести мест в группе. Для всех публикуемых узлов дополнительно проверяются HTTPS-заголовки YouTube, без скачивания видео. Реальная работа из сети телефона требует проверки в Happ.
